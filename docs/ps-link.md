# ProStreet Phase 4: linking the runtime

`runtime/build_ps.sh` links the ProStreet binary (`recomp/out/ps_demo/boot_ps`, arm64, gitignored) from the
translated demo exe and the core runtime. MW's `runtime/build.sh` is unchanged.

## Build order

```sh
tools/.venv/bin/python -I recomp/build_game.py --game ps_demo --exe ~/Games/ProStreet/nfs.exe   # nfs.a, table.c
host/shaders/build.sh lib                  # libsmtranslate.a
media/build_ffmpeg.sh                      # needs third_party/dl/ffmpeg-7.1.1.tar.xz (pinned SHA-256; Setup ships it)
host/audio/build.sh lib                    # libhostaudio.a, libmedia.a
runtime/build_ps.sh                        # boot_ps
```

## What is linked

- **Core** (docs/PROSTREET_PHASE1.md §3): `boot.c` (loader, `host_import`, files), `app.m`, `heap.c`, `threads.c`,
  `interp.c`, the D3D9 → Metal files, D3DX (`d3dx.c`, `d3dx_effect.c`, `d3dx_tex.c`, `readback.c`), `dsound.c`,
  `dinput.c`, `user32.m`, `ws2_32.c`, the CRT shim `msvcr.c`, `win32_more.c`, `registry.c`, `diag.c`, and
  `imports_ps.c` (the import-slot table, generated by `recomp/gen_imports.py`).
- **App shell without MW addresses:** `settings.c`, `server_loader.c`, the upscaling route, `alpha_to_coverage.c`,
  `gpupass.m`, `gpuclients.m`, `rumble.m`, `padfx.m`, `overlay.m`, `probe.m`.
- **`ps_stubs.m`:** 226 "feature off" definitions for the MW feature code the files above still call (materials,
  X360, lamps, widescreen, feedback, sign/shadow diagnostics, private cars, …). It is generated by
  `runtime/gen_ps_stubs.py` from each symbol's own declaration, and it includes the headers, so the compiler checks
  every signature. Each stub returns zero, NULL or false. One exception: `settings_game_language()` answers
  "English US" for the registry's Language value.

## `NFS_GAME_PS`

`build_ps.sh` compiles with `-DNFS_GAME_PS=1`. In the core files that flag removes:

- **MW hooks:** 37 in `diag.c`, `f_006C1990` in `d3d9.m`, `f_0081B4AC` in `dsound.c`, the online-race hooks in
  `ws2_32.c`, and the career-save hook `f_007F4F11` in `boot.c`.
- **Reads and writes of MW guest addresses that run in shared code.** In a ProStreet process these addresses hold
  something else:
  - `dsound.c`'s pause, sim and game-flow reads. They now go through `GAME_PAUSE_REQUEST()`/`GAME_SIM_STATE()`/
    `GAME_FLOW()`, which read as "running, not paused" for ProStreet. Its Snd diagnostics are compiled out.
  - `user32.m`'s front-end, remap, bindings and game-flow reads. The pad acts as in menus.
  - `d3d9.m`'s test automation (autodrive, `BOOT_PURSUIT`).
  - `envcube.m`'s car-reflection size write. The option is off.
  - `boot.c`'s Lua resume address in `dispatch` and the `BOOT_RACE`/online/career setup writes.
  - `threads.c`'s split-screen sound-worker reaper, `registry.c`'s `BOOT_REG` re-read (a MW guest call), and
    `render_query.m`'s tunnel test.
- **The private MW material header:** `materials.h` takes its public branch.
- **The game-folder check in `app.m`:** it looks for `nfs.exe` with `ps_demo`'s regions and tag.
  `runtime/app_fingerprint_test.py` checks that the C side agrees with `recomp/exe_fingerprint.py`, for both
  games, including the real demo exe when it is present.
- **CPUID:** it reports SSE and SSE2 (the translator handles both since Phase 3) but not FXSR.

Everything else reads as before, and MW's build compiles each edited file unchanged.

## Imports

All 332 imports of the demo exe reach `host_import`: 311 have a handler, and the other 21 stop with
`not implemented yet: <name>` (CLAUDE.md rule 6). They are the C++ exception and SEH entry points, `std::string`,
`GetWindowLongA` and an admin check (`docs/PROSTREET_PHASE1.md` §4). Phase 5 implements them as calls reach them.
The demo exe imports nothing from `WSOCK32`. **CRT:** the native MSVCR80/MSVCP80 shim (`runtime/msvcr.c`); the CRT
is not translated as a second module.
